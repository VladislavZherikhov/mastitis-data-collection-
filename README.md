# Что сделано 17.10.2026 (Влад)

## 1. Работа по расписанию (временные окна)

Раньше скрипт делал 5 снимков с интервалом 3 с и завершался. Теперь он работает постоянно и снимает **только во временных окнах**, заданных в `.env`.

- Окна задаются переменными `WINDOW_1`, `WINDOW_2`, `WINDOW_3`, ... в формате `ЧЧ:ММ-ЧЧ:ММ`. Количество не ограничено, номера могут идти с пропусками.
- Окно может переходить через полночь, например `22:00-02:00`.
- Внутри окна каждые `INTERVAL_SEC` секунд (по умолчанию 10) в S3 отправляется пакет: матрица температур, термальный хитмап и снимок с IP-камеры.
- Камеры открываются только на время окна. Если камера не открылась, повторная попытка через 30 с.
- Вне окна скрипт ждёт следующего окна. Время проверяется раз в минуту, потому что у Pi нет RTC и часы могут резко перевестись после синхронизации по NTP.
- При неверном формате окна или если окна не заданы, скрипт сразу останавливается с понятной ошибкой.
- Переменная `SHOTS` удалена, она больше не нужна.

Код: `time_windows.py` (новый), `main.py`, `config.py`.

## 4. Telegram-бот: попробовали и отказались

Был сделан пакет `tg_bot`, который присылал уведомления о запуске и остановке скрипта, о каждом загруженном пакете и об ошибках. Он поддерживал несколько chat_id и не присылал одну и ту же ошибку чаще раза в 5 минут.

**Почему удалён:** Telegram заблокирован, а на Pi нет VPN. Запросы с Pi к `api.telegram.org` падали с `Network is unreachable`, при этом загрузка в Yandex S3 с той же сети работала. Тестовое сообщение доходило только с ПК, у которого есть обход блокировки.

Код бота в git не попал. Если на Pi появится VPN или прокси, бота можно сделать заново по той же схеме. Альтернативы для оповещений: VK-бот, Max или почта через Яндекс SMTP.

## 5. Логи: файл по дням + выгрузка в Yandex Object Storage

Вместо Telegram логи пишутся в файл и выгружаются в тот же бакет.

- Скрипт пишет в `logs/<дата>.log` рядом с собой (например, `logs/2026-10-17.log`) и в консоль. После полуночи начинается новый файл.
- **В конце каждого окна работы** файл текущего дня заливается в S3 и перезаписывает прежнюю версию, так что лог в облаке актуален сразу после окна.
- **После полуночи** вчерашний файл заливается окончательно и удаляется с Pi, но **только после успешной загрузки**. Если сети нет, повтор каждые 10 минут.
- **При запуске** все оставшиеся на Pi файлы прошлых дней догружаются и удаляются (на случай, если скрипт падал или Pi была выключена).
- **При остановке** (Ctrl+C или `systemctl stop`) текущий файл выгружается в последний раз.

Логи в бакете лежат отдельно от данных для обучения:

```
mastitis-bucket/logs/<имя_хоста>/2026-10-17.log
```

Имя хоста в пути нужно, чтобы логи не перемешивались, если Pi станет несколько.

Объём: около 200 КБ в день. Старые логи в облаке удобно чистить правилом жизненного цикла бакета (например, удалять `logs/` старше 90 дней), скрипт для этого не нужен.

Код: `log_storage.py` (новый), `main.py`, `config.py`. Подробные логи (что именно и на каком уровне писать) добавим, когда скрипт будет полностью готов.

## Переменные `.env`

| Переменная | Пример | Описание |
|---|---|---|
| `S3_KEY_ID`, `S3_SECRET` | | ключи доступа к Object Storage |
| `S3_BUCKET` | `mastitis-bucket` | бакет |
| `S3_PREFIX` | `test-grab` | папка для пакетов снимков |
| `IP_CAM_RTSP_URL` | `rtsp://...` | адрес IP-камеры |
| `THERMAL_DEVICE` | `/dev/video0` | термальная камера |
| `INTERVAL_SEC` | `10` | пауза между пакетами внутри окна, сек |
| `WINDOW_1`, `WINDOW_2`, ... | `06:00-08:00` | окна работы |
| `LOG_S3_PREFIX` | `logs` | папка логов в бакете |
| `LOG_DIR` | | папка логов на Pi (по умолчанию `logs/` рядом со скриптом) |

Шаблон — в `.env.example`.
