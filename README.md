# Сбор данных: термальная + IP-камера → Yandex Object Storage

Скрипт для Raspberry Pi 4. В заданные временные окна он каждые 10 секунд делает **синхронный снимок** с термальной камеры и IP-камеры и отправляет пакет в Yandex Object Storage (S3). Копия пакета сохраняется на локальный диск. Скрипт рассчитан на работу без присмотра: переживает обрывы сети, сбои камер и диска, сам отправляет логи и сигнал «я жив».

## Как это работает

1. **Окна работы.** Скрипт работает постоянно, но снимает только в окнах из `.env` (`WINDOW_1=06:00-08:00`, ...). Вне окон он ждёт и догружает в S3 то, что не ушло сразу.
2. **Снимок.** Обе камеры снимают одновременно. Получается **пакет** из трёх файлов:
   - `thermal_<дата_время>.npy` — матрица температур, °C;
   - `thermal_<дата_время>.png` — тепловая карта (хитмап);
   - `ip_cam_<дата_время>.jpg` — кадр IP-камеры.
3. **Диск.** Пакет сохраняется на локальный диск (по умолчанию `/mnt/hdd`). Когда диск заполняется, старые пакеты, которые уже есть в облаке, удаляются в фоне.
4. **S3.** Пакет загружается в облако в фоне, не сбивая интервал съёмки. Нет связи — пакет ждёт на диске и уйдёт позже.
5. **Логи и `status.json`** уходят в S3 каждые 5 минут.

### Где лежат данные

```
mastitis-bucket/
    test-grab/2026-10-21/2026-10-21_17-06-52/     ← пакет (S3_PREFIX / день / дата_время)
        thermal_2026-10-21_17-06-52.npy
        thermal_2026-10-21_17-06-52.png
        ip_cam_2026-10-21_17-06-52.jpg
    logs/<имя_хоста>/
        status.json                               ← «я жив»: состояние прямо сейчас
        2026-10-21/17-10-00.log                   ← логи кусками по 5 минут

/mnt/hdd/test-grab/2026-10-21/2026-10-21_17-06-52/   ← та же структура на диске Pi
```

## Структура проекта

```
main.py                  точка входа: окна -> съёмка -> диск + S3, защита от сбоев
cameras/
    ip_cam.py            IP-камера (RTSP): фоновое чтение, переподключение, таймауты
    thermal.py           термальная камера: матрица температур и хитмап
storage/
    s3.py                Yandex Object Storage: загрузка, разбор ошибок
    local_drive.py       диск: копии пакетов, догрузка в S3, фоновая очистка
core/
    config.py            все настройки из .env
    time_windows.py      временные окна WINDOW_1, WINDOW_2, ...
    log_storage.py       логи: очередь на Pi, отправка в S3 каждые 5 минут
    status.py            status.json - «я жив»
    diagnostics.py       стартовая сводка, итоги окна, маскировка паролей
    problems.py          учёт повторяющихся проблем (без спама в лог)
    watchdog.py          сторож зависаний
    system.py            время (NTP), питание/перегрев Pi, защита от второго экземпляра
    logmarks.py          пометка «важное» для логов
documentation/           подробная документация (см. ниже)
.env.example             шаблон настроек
requirements.txt         зависимости Python
```

## Запуск на Raspberry Pi

Нужен Python 3.10 или новее (в Raspberry Pi OS Bookworm стоит 3.11, в Trixie — 3.13).

```bash
git clone https://github.com/VladislavZherikhov/mastitis-data-collection-.git main_script
cd main_script
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env                # ключи S3, адрес IP-камеры, окна работы
python3 main.py
```

Перед первым запуском проверь:
- **Диск смонтирован:** `findmnt /mnt/hdd`. Если диска нет, оставь `DRIVE_MOUNT=` пустым: пакеты пойдут только в S3.
- **Путь к термокамере:** лучше указать постоянный путь из `ls /dev/v4l/by-id/`, а не `/dev/video0` (см. [cornercases.md](documentation/cornercases.md)).

Для работы без присмотра скрипт нужно запускать как **systemd-сервис** с автоматическим перезапуском. Что нужно от сервиса — в разделе «Что нужно от автозапуска» в [cornercases.md](documentation/cornercases.md).

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `S3_KEY_ID`, `S3_SECRET` | — | ключи доступа к Object Storage (**обязательно**) |
| `S3_BUCKET` | `mastitis-bucket` | бакет |
| `S3_PREFIX` | `test-grab` | папка для пакетов (в S3 и на диске) |
| `IP_CAM_RTSP_URL` | — | адрес IP-камеры (**обязательно**) |
| `THERMAL_DEVICE` | `/dev/video0` | термальная камера (лучше путь из `/dev/v4l/by-id/`) |
| `INTERVAL_SEC` | `10` | пауза между пакетами внутри окна, сек |
| `WINDOW_1`, `WINDOW_2`, ... | — | окна работы `ЧЧ:ММ-ЧЧ:ММ`, сколько угодно, можно через полночь (**хотя бы одно**) |
| `DRIVE_MOUNT` | `/mnt/hdd` | диск для копий пакетов; пусто — не сохранять |
| `DRIVE_USAGE_THRESHOLD`, `DRIVE_USAGE_TARGET` | `80`, `70` | очистка диска: начать при N % занятого места, чистить до M % |
| `DRIVE_FREE_THRESHOLD`, `DRIVE_FREE_TARGET` | — | то же по свободному месту (`20GB`, `50GB`); важнее процентов |
| `DRIVE_MIN_AGE_DAYS` | `1` | не удалять не выгруженные в S3 пакеты моложе N дней |
| `DRIVE_MIN_FREE` | `1GB` | аварийный минимум: при меньшем свободном месте пакеты только в S3 |
| `LOG_S3_PREFIX` | `logs` | папка логов в бакете |
| `LOG_UPLOAD_INTERVAL_SEC` | `300` | как часто отправлять логи и `status.json`, сек |
| `LOG_LEVEL` | `INFO` | подробность логов: `INFO` или `DEBUG` |
| `LOG_DIR` | `logs/` | очередь неотправленных логов на Pi |
| `MAX_PENDING_UPLOADS` | `6` | сколько пакетов может ждать загрузки; остальные ждут на диске |
| `WATCHDOG_TIMEOUT_SEC` | `600` | через сколько секунд без прогресса скрипт считается зависшим и перезапускается |
| `CLOCK_SYNC_WAIT_SEC` | `300` | сколько при запуске ждать синхронизации времени |

Ошибка в `.env` (неверное окно, порог, нет ключей) останавливает скрипт с понятным сообщением и кодом выхода 2.

## Как следить за работой

- **`logs/<хост>/status.json` в бакете** — главное: когда скрипт последний раз выходил на связь, идёт ли окно, время последнего снимка, счётчики, активные проблемы, состояние диска и Pi. Если `updated` старше 10–15 минут, Pi не на связи.
- **Логи в бакете** — `logs/<хост>/<дата>/*.log`: стартовая сводка, строка на каждый пакет с таймингами, итоги окон, все ошибки.
- **На Pi** — консоль или `journalctl` (при запуске как сервис).

Подробно — в [logging.md](documentation/logging.md).
